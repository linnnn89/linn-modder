# 二次元素材抽屉

适用于立绘、头像、表情、服装变体、Live2D 和动漫风 3D，不限策略游戏。先确定游戏接收哪一种资产，不能把“二次元 MOD”自动理解成大量生成 PNG。

## 先做一条完整角色链

固定角色 ID、作品/服装版本、色板、脸型/比例、裁切安全区与用途；建立角色 → 显示名/语言 → 头像/立绘 → 模型/表情 → 语音的映射。引用原作美术要记录来源与许可；跨作品素材尤其不能把可浏览当作可再分发。源图获取/生成按[素材来源与 PSD](sourcing-and-psd.md)。

| 类型 | 常见失误 | 应保留/验证 |
|---|---|---|
| 头像/半身/全身图 | 每张图脸大小和视线不同，自动裁掉发饰 | 统一头部参考位置和安全区；在实际圆形/矩形 UI 遮罩中观察 |
| 表情/换装 | 独立生成导致脸型、光源和姿势漂移 | 从批准底图派生；共同画布/锚点；遮挡层与透明边缘一致 |
| 精灵动画 | 帧顺序、脚底 pivot、左右方向或阴影跳动 | 时间与帧布局来自目标合同；观察循环、脚底和切换状态 |
| Live2D | 只交 atlas 或平面 PSD，却声称模型完成 | 图层/部件、遮挡补画、网格/参数/物理、SDK 版本分别检查 |
| 动漫风 3D | 骨架/尺度/表情/材质与目标不同 | 映射骨骼、权重和动作；toon 材质/轮廓在目标光照下观察 |
| 成套转换 | 只替换人物名和头像，剧情/技能/模型仍指向旧 ID | 用一个角色完整贯通数据、资源和场景后再批量 |

整理 `source/editable/prepared/engine-output`，记录已批准底图和导出参数。可动资产需要补齐被遮挡的身体、发丝、关节部分；自动抠图不能还原不可见结构。UI 面板和字体使用[UI MOD](../../ui-mod/SKILL.md)，避免由人物画风决定文字可读性。

联网查对应版本的[Live2D、VRM、Unity 日文文档及中文/英文资料](../../mod-research/references/art-and-ui-sources.md)；不要求下载模型或训练权重。大型成品学习以目录、清单、ID、数据依赖和故障为主，禁止复制整包素材进入工具库。

需要组织完整内容包时，按需读取知识库的 `techniques/content-mod-design.md`：资源职责分层、稳定 ID 与引用图、版本合同、安装依赖及恢复能力。MCP 使用 `manual_read(collection="knowledge", path="techniques/content-mod-design.md")`；也可搜索 `content-mod`。原则不依赖特定成品或安装位置，不要在 skills 集合中跨目录读取。
