# 文本、结构化数据与脚本抽屉

## 改前取证

读取原始字节确认 BOM、UTF-8/UTF-16/特定旧编码、换行和末尾换行；解码失败保留失败位置，不用 `errors=ignore/replace` 后写回。控制台乱码先检查终端编码，不据此改源文件。识别真实方言与加载代码：`.json` 可能带非标准控制字符，`.yml` 可能是游戏私有语言表。

选定正确读取者后先做无改动往返。保持未知字段、注释、重复键语义、数组顺序、数值精度、字符串前导零与大小写路径；不要顺手格式化整个文件。若序列化器不能保留合同，改用官方编辑器或局部有边界的修改，而非静默丢信息。

## 各格式最容易破坏什么

| 对象 | 修改前必须查清 | 验证 |
|---|---|---|
| JSON/JSONC | 严格 JSON 还是带注释/控制字符的方言；重复键、null/缺省、大整数 | 解析、schema/必填字段、记录数、ID 唯一性与未改记录；普通 `json.loads` 通过不等于完整 schema 验证 |
| CSV/TSV | 分隔符、引号、嵌入换行、编码、列顺序 | 用 dialect 解析；确认列数/类型；禁止 Excel 自动转日期或去掉前导零 |
| YAML/INI/XML | 注释、section 大小写、重复项、namespace、节点顺序 | 使用安全解析和兼容 writer；XML 不解析外部实体；不调用可执行对象反序列化 |
| 游戏本地化 | 语言头、键、转义、插值和富文本 | 键不变、参数不丢失；交给[字体与本地化](../../ui-mod/references/fonts-and-localization.md)验证显示 |
| Lua/JS/游戏脚本 | 运行时版本、模块路径、加载顺序、事件生命周期 | 静态/语法检查后，按授权执行最小事件；源代码、字节码和打包容器是不同交付物 |
| SQLite 或其他数据库 | 实际 schema、索引、事务与外键 | 在副本事务内修改并核对完整性；不要把数据库当文本替换 |

## ID 和关联比能解析更重要

人物表、技能表、剧情表、贴图和模型常用同一稳定 ID。保留原有 ID；新记录使用官方命名/项目后缀，检查碰撞、缺失引用、名称/资源路径。不要按显示名批量匹配，也不要将字符串 ID 转数字。按目标构造最小数据链，例如人物 → 技能 → 效果 → 图像。

工坊包存在不代表附带的本体补丁已安装。模组工程基线与当前游戏 build 分别记录；游戏更新时按字段/ID 对比，避免用整份旧表覆盖新增字段。修改运行中的配置/存档还可能被进程或云同步写回；仅在已授权的停写状态下部署。

严格解析失败只能说明这个解析器不接受输入；不能自动推断游戏损坏。宽松解析可辅助调查，但需标记选项，不能把绕开异常当修复或兼容证据。
