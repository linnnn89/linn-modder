# CK3 启动崩溃案例：决议 widget 未显式初始化 controller

**案例版本：CK3 1.20.1.1。** 下文保留故障机制和修复方法，使用中性脚本名称举例。该版本案例的启动问题已获运行确认，自定义界面与完整活动流程仍需分别验收。

## 原因与证据

游戏在加载阶段发生 `C0000005 / EXCEPTION_ACCESS_VIOLATION`。本次 minidump 的故障线程同时保留了：

- 触发加载的自定义决议及其 GUI 对象。
- 空的控制器指针。
- 读取空地址的故障指令。

决议的 `widget` 只指定了 `gui`，没有显式声明 `controller`。同版引擎的解析路径在处理 `controller` 时创建控制器对象；缺失该字段的对象保持为空，后续加载直接访问它而崩溃。其他决议出现相同写法时，应检查具体控件，不能只修复故障栈里的一处。

同版 `game/common/decisions/_decisions.info` 将控制器默认值写为 `default`，并列出其数据上下文为 `EventWindowWidget`。文档中的默认值不能替代实际运行证据；遇到这种空控制器故障，应显式声明匹配的控制器。不据此推断所有 CK3 版本都会因省略该字段崩溃，也不把任意 `C0000005` 都归为此问题。

决议会在启动阶段加载，尚未点击该决议并不能隔离这种错误。日志末尾的人物特质本地化警告不等于致命原因；应结合异常线程、脚本对象和故障指令判断。

## 错误写法与正确方式

本次导致空控制器的写法：

```text
widget = { gui = "example_planner" }
```

不需要专用行为的自定义筹备界面，显式使用默认控制器：

```text
widget = {
    controller = default
    gui = "example_planner"
}
```

示例对应 `gui/decision_view_widgets/example_planner.gui`，文件名与 `gui` 值一致；`example_planner` 是占位名称，须替换为工程实际定义。

若界面需要选项列表、头衔或其他专用控制器，应按当前版本 `_decisions.info` 及原生示例显式选择匹配的控制器；不要一律替换成 `default`。新增步骤、`show_from_start` 和相应按钮字段也应分别遵守本版合同。

## 修复和防回归

1. 保留本次 crash 文件夹、精确版本、启用组合和受影响脚本。异常堆栈缺少函数名时，转储中的对象名和空指针可以缩小范围；不要仅凭最后一条日志批量改脚本或归咎于图片、硬件。
2. 同步修正生成源、工作区生成结果与实际安装副本，只重建受影响决议，不因此重建人物、画像或整个 MOD。
3. 在生成结果的具体 `widget` 块上检查控制器声明与 GUI 路径。先确认旧结果失败，再确认修复结果通过；括号检查或整文件出现一个 `controller` 字符串均不足以保护调用点。
4. 备份受影响文件，使用路径白名单定向安装，保留原存档与配置；安装前后核对受保护文件。不要把存档打入 MOD 包。
5. 复验保持相同启用组合，确认进入主菜单并检查新一轮日志，再验证相关决议入口、按钮及实际界面。到达主菜单不证明活动、AI、旅行或存读流程全部通过。用户接管测试后停止自动化。

## 证据与适用边界

这个案例支持“核对具体 widget 并显式初始化控制器”的处理方法，不构成所有版本或全部决议的保证。复现日志、转储和安装回执保留在使用者自己的工程中，公共手册不包含私人目录、角色键或游戏文件。收尾范围见[验证与交付](verification.md)。
