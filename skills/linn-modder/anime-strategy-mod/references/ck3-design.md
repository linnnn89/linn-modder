# CK3 MOD 设计与实现

用于新机制、人物、脚本、画像、旧档或兼容修改。先用现有文件确认版本、DLC、播放集、依赖和本轮存档；缺失信息标未知。只做设计时交付设计，不要求安装游戏。已有工程继续使用其清单、生成器与稳定 ID。

## 先写一张功能卡

在现有设计文档中写清下列内容；小改动用一段话即可，无须新建一套配置系统。

| 项目 | 要回答的问题 |
|---|---|
| 玩家行为 | 从哪个入口，对谁做什么，玩家怎样看到结果？ |
| 执行对象 | 执行人、目标角色、头衔/领国分别是谁？目标在翻页、延迟后是否仍正确？ |
| 状态变化 | 读取和修改哪些字段？失败、取消、再次执行分别发生什么？ |
| 玩法范围 | 玩家/AI、普通玩法/作弊、费用与频率按用户设计决定，不自动添加平衡限制。 |
| 持久性 | 新开局、旧档、存读档、死亡或继承中，哪些状态需要保留？只展开相关情况。 |
| 验收 | 一次操作前后的具体差异是什么？本轮能做静态检查还是实际运行？ |

先实现一个完整的小功能，再扩展人物或事件数量。设计输出至少包含功能卡、涉及文件、依赖/覆盖范围及验收办法；未知接口附查证任务，不填看似合理的命令名。

## 选择数据层

| 需求 | 首选位置与要点 |
|---|---|
| 初始人物、家族、头衔与书签 | `history/`、相应 `common/` 定义；书签展示须对应真实角色与持有者。改历史不等于迁移旧档。 |
| 人物能力、文化、宗教 | 相应 `common/` 数据库；核对本版类型和修正字段，拆开定义与存档运行时对象。 |
| 对另一角色操作 | `common/character_interactions/`；分别设计显示、可用、接受、执行和 AI 条件。 |
| 玩家决策、事件链 | `common/decisions/`、`events/`；共享重复逻辑才提取 scripted effect/trigger。 |
| 生命周期通知 | `common/on_action/`；读本版钩子说明，用自有回调接入，不覆盖整段原生效果。 |
| 界面与文本 | `gui/`、`common/scripted_guis/`、`localization/`；界面展示和最终写入分开核对。 |
| 图片与人物外观 | `gfx/` 与实际调用控件；先选下面的 2D/3D 路线。 |

采用自有文件和命名空间；列出需要覆盖的原生/依赖对象及原因。CK3 各数据库、GUI 和文件路径的合并规则不同，不能统一套用“最后加载获胜”。`replace_path` 只用于有意替换整类内容的设计。脚本来自本版 `.info`、原生调用实例或已导出的 `script_docs`/`dump_data_types`，再对照工具作者资料。

## 脚本与状态的最小合同

- **明确 scope。** 标出入口提供的 root、保存的目标和嵌套 scope。菜单翻页、延迟事件和回调检查目标引用；缺失时停止该操作并给出实际原因，不默默改成玩家本人。
- **只结算一次。** 显示/可用条件不承担状态写入；费用、成功效果、失败恢复各有清晰位置。提示框预览与执行分别检查；`hidden_effect` 不能修复错误 scope。
- **保留稳定键。** 人物身份、当前身体、事件 ID、本地化键分别管理。给事件声明 namespace；现有萌战工程的数字尾段约束见经验档 Gotcha 3，不推导其他版本的引擎算法。
- **按需要保存。** 死亡重建才需要稳定槽位与当前化身、队列、持久进度分离；开局和重建共用人物配置。创建前查现有有效化身；继承、婚姻、亲缘和领地按各自合同恢复。
- **控制遍历。** 优先通知、目标集合或待办队列；按角色执行的回调中再遍历全体会放大成本。只在有补漏需求时增加低频巡检，记录扫描次数与日志增量后再优化。
- **改生成源。** 生成器负责的内容从源头重建；共享手写文件按键或语法块修改，保留注释、编码与他人的新修改。不要用行首正则把嵌套块当顶层定义。

本地化使用 `localization/<language>/..._l_<language>.yml`，UTF-8 BOM 与匹配的语言头；保护变量、格式标记和文本键。平衡数值与玩家文案分开，提示框不塞制作备注。

## 二次元人物与肖像

- 人物属性、能力、关系与阵营按 [人物原则](character-design-principles.md)；继续星誓萌战时再读 [项目约定](ck3-moe-project.md)，保留用户已确认安排。
- **原生 3D：** DNA/ethnicity、模型、骨骼、材质与动画按实际路线核对。PNG 不能直接替代人物模型。
- **框架 2D：** 先读取已用画像框架的稳定身份映射和 GUI 接口；登记人物使用 2D 分支，普通 NPC、自创人物及其他 MOD 保留各自分支。不要为了几名角色全局改文化 ethnicity。
- 实测主立绘、小头像、关系栏等实际控件的裁框、遮罩和交互。采用按脸部定位的独立裁图，不能把整张立绘缩小视作适合所有控件。
- 需要新素材时先取官方参考；Codex 可用 GPT Image 制作缺失素体或变体。PSD 由真实编辑器组层并重开检查，详见 [素材与 PSD](../../asset-pipeline/references/sourcing-and-psd.md)。

## 收尾与兼容

先做本轮相关的编码、引用、作用域、生成一致性与依赖检查。已有 Tiger 时可让它加载同版原生文件和依赖 MOD，聚焦新增报告；用法见 [验证](verification.md)。工具误报或版本滞后需逐条核对，不为全绿屏蔽整类问题。

核对工作区产物、外部 `.mod` 路径、内部 `descriptor.mod`、安装哈希与实际播放集。DLC 条件能控制执行，不保证解析器认识专用符号。历史新增通常走新局；旧档补入才设计幂等迁移，保留已有效状态和待执行引用。

只验收变更涉及的行为：人物修改看实际角色与关系，按钮看指定对象前后值，轮回看一次死亡至重建及重复读取，画像看实际控件。未运行游戏就保留 `not-tested-in-game`；主菜单成功仅证明该组合能启动。
