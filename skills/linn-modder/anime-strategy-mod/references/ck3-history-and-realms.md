# CK3 历史、领国与开局

用于新增分封、搬迁阵营、排查飞地、修正首府、法理或书签。先确定目标日期，以及问题来自新开局还是已有存档。下文讨论历史输入、生成与检查方法；离线回放不代替游戏中的地图和旧档验收。

## 先分清几种归属

| 字段或对象 | 表达什么 | 排查时注意 |
|---|---|---|
| 头衔 `holder` | 谁持有这个头衔 | 同一人物还可能在别国持地；不能只看本次分配表 |
| 历史 `liege` | 该头衔的政治从属输入 | 多头衔持有人会使实际领国归属复杂化，须结合人物及所有相关头衔判断 |
| `de_jure_liege` 与静态头衔层级 | 法理父级 | 法理属于某国，不表示已成为其封臣 |
| 头衔 `capital`、人物直辖县 | 首府安排与可用领地 | 改首府键不能补出君主缺失的直辖县 |
| 书签、清单展示字段 | 推荐入口和人物资料 | 卡片写着某王国，不证明实际持有人就是推荐角色 |
| 来源县、服务锚点 | 生成来源或运行时定位依据 | 未必表示当前所有权，不能随搬迁批量改成新封地 |

地图出现异国飞地时，先查持有者和政治链。将已持独立王国的人物再次分到另一帝国的县，可能产生跨国归属和首府偏移；只改法理无法解决。反过来，某个公国虽已在本国法理内，缺少政治归属仍可能保持独立。

这不表示一人持有多个王国就是错误。检查应回答：该人物的自持头衔和其他封地是否落入互不相容的政治安排。跳过 `liege = 0` 的自持王国，会漏掉“独立君主兼持外邦县”；应把自持部分作为同一归属组，而非把每个王国都算成一个冲突。

## 按日期还原有效历史

不要拿搜索命中或最后一个文本块当最终状态。应使用项目已有回放入口，合并目标版本原生数据、依赖和本 MOD 的相关覆盖层，分别求出目标日期的有效持有人、宗主、法理及政体。静态 `common/landed_titles/` 中的父级也可能是没有历史字段时的依据。

核对同日多层覆盖时，保留来源顺序和字段级结果。多个文件提到同一头衔不一定重复分封；后续层可能只接管部分字段。旧基线之后有文件变化，就刷新受影响的头衔和来源，不把过期元数据当作当前故障。

需要将历史改动限定在专用书签时，可以在目标日期写入覆盖，再在后一日期恢复此前有效历史。后一日期用于隔离其他开局日期，不会在游玩到第二天时自动搬回领地。恢复值应来自修改前、恢复日期的有效状态；不能拿已修好的世界重新生成“原始状态”。具体日期按工程自己的书签范围设计。

这种日期隔离只覆盖所写的历史字段。`common/landed_titles/` 中的静态首府等定义不会随后一日期自动恢复，仍须单独说明对其他开局的影响。

涉及已有布局时，先固定候选计划与修改前状态，再生成、验证和安装。一次性迁移完成后禁止重取前态的入口，应直接拒绝重放或复用已验证候选；不要为了验证再执行一遍分封。需要重建时，将原始批次输入与当前布局分开，避免新清单的封地反向污染旧场景。

## 分地与搬迁要检查双方

开始分配前，核对目标人物在相关世界中已有的头衔和雇主。保留其稳定 key、history ID、身份特质、画像索引与衣柜；迁地不重新造人。现任有地领主至少有一块可用直辖县，拟作廷臣的人物则核对是否仍意外持地。

阵营搬迁同时涉及接收地、旧地和周边领主。将旧县交给当地持有者时，不能顺带搬走不属于目标阵营的封臣，也不能删除失地的原生人物。迁移范围来自明确的名册身份，不能因“原来同属一位领主”就把所有人一并迁走。

首府同时检查头衔定义、有效直辖县和实际宗主链。书签则核对角色 ID、该日头衔持有人、首府与推荐说明。清单中的 `primary_title`、起始位置、来源县及分组锚点分别查其调用者，只更新确实表示当前布局的字段。

## 地图连通性需要真实邻接

县中心距离适合筛候选，不足以证明连通。需要判断国土是否被切断时，从目标版本的 `provinces.png`、`definition.csv` 与男爵领 province 绑定恢复真实县域，再读取 `adjacencies.csv` 等原生邻接依据。没有地理省份的家族等县级头衔应单独处理，不能当作缺失地图数据。

分别计算陆地相接、可通行连接和法理范围，并尊重不可通行边界。大河渡口、海峡与海岛不能混成一条“陆地连通”结论；海岛分离也未必是需要修复的飞地。只因质心距离较近就补一条陆桥，会改变问题本身。

局部修复复用已有地图基线，仅检查本轮转出、转入及可能被切断的周边国家。确需全图审计时才扩大范围，并保留天然海岛、原生冲突和本 MOD 新增问题的区别。

## 验收看有效结果

最小检查包含目标日期的前后差异、受影响人物的持地与从属、首府、相关法理层级，以及旧地和接收地的连通变化。存在日期恢复设计时，再核对恢复日期的有效值。项目已有原生悬空关系或冲突时保留基线，不为让检查通过扩大修复范围，也不将新增问题写入允许列表。

离线回放证明的是脚本输入及其解析模型下的结果。安装哈希一致证明的是文件落位；存档字节不变证明没有改写它。游戏中的宗主最终选择、首府图标与新局表现仍需实际开局确认，已有存档不会因修改历史而自动迁地。交付与旧档边界见[验证与交付](verification.md)。
