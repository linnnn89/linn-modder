# CK3 画像绑定与衣柜维护

用于已有 2D 框架的立绘、头像、默认衣装和衣柜维护。CK3 原生人物是 3D 路线；2D 接入方式取决于所用框架，文件名、尺寸与分支结构不能跨框架套用。先确定是图片质量问题、控件裁框问题，还是身份与选择器没有接通。

## 从实际控件追到图片

图片存在、尺寸正确，只说明有一个可读素材。显示还需要完整调用链：**当前人物身份 → 对应画像分支 → 选择条件与衣装状态 → 实际纹理 → 控件裁框和遮罩**。主立绘、小头像、中型头像和关系栏可能各有入口，修好其中一个不代表其他入口也已覆盖。

| 现象 | 优先核对 |
|---|---|
| DDS 已生成，头像仍空白 | 实际控件、身份选择器、可见性分支、纹理路径与最终回退 |
| 换装后仍显示默认图 | 衣装状态、默认图闸门，以及是否存在另一份无条件画像定义 |
| 迁地或轮回后串脸 | 稳定 key、当前化身与身份绑定；不要用新头衔替代人物身份 |
| 只有某个大小的画像不显示 | 该控件专用路由及已审核覆盖范围 |
| 只见头发、帽子或下巴被裁掉 | 实际裁切输入、脸部定位和坐标变换，再查 widget 裁框 |
| 普通 NPC 或其他 MOD 人物外观消失 | 全局可见性条件、3D 回退和第三方分支是否被覆盖 |

生成头像时漏接选择器，文件就不会被界面调用。同一个画像键若有两份定义，一份带默认衣装闸门，另一份无条件生效，也可能使衣装选择失效。不能因为图片齐全就跳过绑定，也不能盲目保留文件中后出现的定义。先比较结构与条件，再决定保留哪份；完全相同的重复块和有行为差异的重复块应分别处理。

## 默认图、追加衣装与人物身份分开维护

换默认图、追加衣装、修头像和新增人物是不同任务。追加衣装不自动替换默认图，也不重新分配人物索引。已有稳定 key、身份特质、画像索引及已发布的衣装 ID 保持原意；新衣装沿用项目的权限、菜单和保存方式。

默认衣装的条件要按状态取值检查：未设置、默认值，以及已配置的每个非默认衣装。非默认状态下默认图应按设计退出，选择器不应同时落入另一条无条件分支。权限判断与显示状态分别验证，不能用“图片能打开”证明菜单或权限生效。

中型头像可能只覆盖经审核的人物子集。重建时应保留现行路由，不能因原批次生成器只认识几十人，就覆盖后来扩展的名单；也不能把不在该子集中的所有人物直接判作缺陷。遇到未知身份、重复定义或无法识别的 gate 时，先停止写入并定位来源。保留普通 NPC、自创人物和其他模块已经使用的分支。

## 裁图先定位脸，再换算坐标

从实际用于裁切的文件量头脸位置，先将框叠回同一张图确认，再生成目标头像。原图、工作副本、1024 主图和联系表各有坐标系，不能直接互用框坐标。抬手、帽檐和长发会扩大主体包围盒，用全身高度的固定比例估头高很容易切掉下巴。

尺寸要求从实际控件和纹理测量，不将某套框架的画布和头像比例当作 CK3 通用标准。主图适合按完整主体排版，头像应按脸部独立裁切。透明边界正确也不保证主图在人物面板中位置合适；新取景须与已验收原版对照，明显更差就保留原版。

批量预览标注稳定 key 与衣装 ID，标签必须完整可读。先看联系表定位问题，仅对看不清的格子补局部图；修改后复核受影响部分。不要为了修头像重新去背，也不以检测分数替代面部、发饰和配件的目视检查。

## 来源、透明图与游戏成品分开记录

优先复用已有合格 alpha 和已验收产物。需要新处理时，按当前工程的素材规则选择方法：简单背景可考虑保留源 RGB 的本地 alpha 处理，复杂轮廓则使用已配置且获得授权的工具。具体生成方式、重绘容许程度和模型限制由当前任务决定。

“官方图”“抠图”“最终立绘”各有含义。带背景的官方 CG 仍可能残留墙面或旁人；视觉上的棋盘格可能已被画进 RGB，而非真正透明。检查实际 alpha 取值、浅深底合成和完整主体；白衣、细发、武器、翅膀等不能仅靠全局删色处理。生成式去背可能轻微重绘，应如实记录方法，不能声称逐像素保真。

清单分别保留原图、处理输入、明确登记的抠图和运行成品及其来源。路径存在、SQL 已同步或哈希与清单声明相符，都不能证明未看过的边缘质量，也不能证明某个素材由 Qwen 制作。缺失记录先查源清单和批次证据，不按文件名推断来源；清单错误也不等于当前游戏缺图。

## 生成、提交与验收

先读当前清单和生成入口，确认会写哪些文件。修改生成源后在临时目录验证受影响输出；涉及共享画像、选择器或衣柜的入口应拒绝冲突定义，不能只修改第一处同名块。已有事务提交入口时复用其锁、前像核对与回滚，不另造一条绕过检查的安装路径。

共享文件在提交前再次核对当前状态；已被其他任务修改时合并本轮键或语法块，不拿旧文件整份覆盖。仅安装变更清单内的图片和相关文本，保护原素材、已确认默认图与无关衣装。

离线检查覆盖对应身份、状态分支、素材格式和生成一致性；图片目视只记录实际看过的版本。游戏验收则在出问题的控件中查看目标人物，涉及分支时补普通或第三方人物，涉及衣柜时实际切换并按需要存读档。未运行游戏就分别报告素材、绑定及安装结果，不写“显示正常”。详见[验证与交付](verification.md)。
