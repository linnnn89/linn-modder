# UI 布局与状态抽屉

## 先确定控制布局的层

记录页面/控件 ID、父容器、anchor/pivot、参考分辨率、缩放模式、最小尺寸、裁剪和层级。判断布局来自 Unity UGUI/UI Toolkit、Godot Control、Ren'Py screen 或游戏私有格式；识别依据不足时先读样本和目标版本文档。

优先官方主题/模组覆盖和已有控件属性。整文件替换可能覆盖其他 mod；新控件使用项目命名空间，记录覆盖文件与依赖，不自动引入额外 loader。

## 皮肤与图集

- 换图保留 sprite 名称/ID、rect、pivot、pixels-per-unit 和九宫格边界。不同尺寸重新检查 atlas 元数据和引用；不要只覆盖一张大图。
- 检查裁切、旋转、padding、边缘外扩与采样；缩小时邻图串色需要查 padding/mipmap/过滤，不能直接认定原画有问题。
- 按目标保留 straight/premultiplied alpha、sRGB/linear、压缩、mipmap 策略。UI 通常有专门导入设置，不能给所有纹理统一关闭或开启 mipmap。
- 对同一按钮补全所需状态；装饰层不要拦截点击，视觉范围与点击范围要一致。

## 用真实任务验证

至少覆盖用户主要分辨率/比例和一个边界配置；只有目标支持时才加超宽屏、高 DPI 或手柄场景。执行打开页面 → 切换标签/滚动 → 操作控件 → 关闭/重开，核对焦点顺序、取消返回、tooltip、遮罩和弹窗层级。输入方式按用户实际使用验证。

对照相同存档/场景的前后状态，检查日志中的缺资源、绑定和脚本错误。数据驱动的布局还要观察长名字、空列表和动态数值；无需为无关页面扩大测试。未运行游戏时交付预览和静态检查，保留“交互未验证”。

原理与版本入口：[Unity/Godot/Ren'Py 官方资料](../../mod-research/references/art-and-ui-sources.md)。
